## 3. P0: 현재 구조 안에서 먼저 개선

`AGENTS.md`의 허용 범위인 모바일 메뉴, 문의 동선, SEO, 히어로 문구에 한정한다. 교육 페이지 신설이나 CMS 확장은 이 단계에 포함하지 않는다.

### P0-1. 모바일 메뉴 복구

**목표:** 모바일에서도 PC와 같은 목적지에 접근한다.

- 홈과 `/activity` 상단에 메뉴 열기·닫기 버튼을 제공한다.
- 기존 메뉴 순서와 목적지를 보존한다. 활동 페이지에서 홈 섹션으로 이동할 때는 `/#manifesto`처럼 기존 홈 해시 링크를 사용한다.
- 기존 WATCH와 활동 페이지의 PORTFOLIO HOME 버튼을 유지한다.
- 추가할 문의 진입점은 메뉴 하단에 둔다. 로고·WATCH·메뉴 버튼이 좁은 화면에서 겹치지 않도록 한다.
- 버튼에 명확한 이름과 `aria-expanded`, `aria-controls`를 제공한다.
- 링크 선택, Escape, 메뉴 외부 선택으로 닫히게 한다. 닫으면 포커스가 열기 버튼으로 돌아가게 한다.
- 메뉴 방식은 간단한 드롭다운을 우선 검토한다. 배경을 막는 모달 방식이면 포커스 이동과 스크롤 잠금까지 구현해야 한다.
- 기존 600px 경계를 우선 적용하고, 중간 폭에서 링크가 충돌할 때만 메뉴 전환 범위를 조정한다.

수정 예상 파일: `src/App.tsx`, `src/components/ActivityPage.tsx`, `src/index.css`.

### P0-2. 히어로 문구 명확화

**목표:** 기존 브랜드 인상과 함께 서비스 범위를 한 번에 이해시킨다.

추천 문구:

```text
하고싶은거
다함.

WE CREATE. WE TEACH.
AI 영상·웹 제작부터 실무 교육까지.
아이디어를 결과물로, 배움을 실전으로 연결합니다.

[작품 보기 →]    제작·교육 문의 ↗
```

- 큰 제목·큐브·라임 포인트·현재 배치를 유지한다.
- `작품 보기 →`는 현재 `#actions` 연결을 그대로 사용한다.
- 문의는 보조 텍스트 링크로 둬 큰 버튼을 여러 개 늘리지 않는다.
- 현재 CMS의 `userRole` 바인딩은 유지한다. 저장된 값을 강제로 덮어쓰지 않는다.
- 두 개의 제목용 div는 시각적 줄 구성을 유지하면서 의미상 하나의 `h1`으로 묶는 방식을 검토한다.
- 본문과 버튼이 320px 화면에서도 자연스럽게 줄바꿈되는지 확인한다.

수정 예상 파일: `src/App.tsx`, 필요 시 `src/index.css`의 해당 요소 규칙만 보완.

### P0-3. 문의 동선 연결

**목표:** 작품을 본 방문자가 제작 상담 또는 교육 상담을 바로 시작한다.

동선:

```text
홈 / 활동 페이지
    → 홈 하단 문의 영역
        → 제작 문의
        → 기관·기업 교육 문의
```

푸터 직전 또는 푸터 내부에 짧은 문의 영역을 추가한다. 문의용 `#contact`는 추가 앵커로 사용하고 기존 앵커는 유지한다. `/activity`에서는 `/#contact`로 연결한다.

```text
LET'S MAKE IT REAL.
만들고 싶은 일, 함께 시작해요.

제작 문의 ↗                 기관·기업 교육 문의 ↗
AI 영상 · 웹 제작           대상과 목적에 맞춘 실무 교육
```

연결 기준:

- 교육 코드에 있는 폼 후보는 `VITE_APPLY_FORM_URL` 또는 기본값 `https://forms.gle/w1cTzZYUCGkqdDTT6`다. 실제 설정값과 폼의 현재 목적·접수 가능 상태는 연결 전에 확인한다.
- 이 폼이 교육 상담 전용이면 제작 문의를 같은 폼으로 보내지 않는다. 제작 문의를 받을 실제 이메일·채널·폼을 확인해 연결한다.
- “카카오톡 @AI다함스튜디오”라는 안내 문구는 있지만 직접 연결 URL은 코드에서 확인하지 못했다. URL을 추측해 만들지 않는다.
- P0에서는 기존 외부 접수 수단을 활용한다. 자체 문의 DB나 새 CMS 입력 기능을 만들지 않는다.
- 현재 확정된 개인 모집 과정이 없으므로 P0에서는 “12월 수강 신청” 버튼을 노출하지 않는다. 실제 모집은 후속 교육 단계에서 연결한다.

외부 문의폼에서 받을 내용의 권장안:

| 제작 문의 | 기관·기업 교육 문의 |
| --- | --- |
| 이름/소속, 연락처, 제작 분야, 목적, 희망 납기, 예산 범위, 참고 자료 | 담당자/기관명, 연락처, 교육 대상·인원, 희망 일정, 온·오프라인, 교육 목표, 예산 범위 |

폼 항목 변경은 사이트 코드 작업과 별도 운영 작업이다. 문의 채널이 확정되기 전에는 연결되지 않는 버튼을 공개하지 않는다.

### P0-4. 검색·공유 정보 정리

**목표:** 사이트와 공유 링크에 제작·교육 브랜드의 역할을 설명한다.

추천 초안:

| 경로 | 제목 | 설명 |
| --- | --- | --- |
| `/` | DO DAHAM \| AI 영상·웹 제작과 실무 교육 | AI 영상과 웹서비스 제작부터 기관·기업 실무 교육까지. DO DAHAM의 대표 프로젝트와 교육 현장, 활동 기록을 만나보세요. |
| `/activity` | 교육 현장·활동 기록 \| DO DAHAM | DO DAHAM의 AI 교육 현장과 기관 출강, 언론 보도 및 인터뷰 기록을 확인하세요. |

구현 항목:

1. 초기 HTML의 `lang`을 `ko`로 맞추고 홈 description과 canonical을 제공한다.
2. 초기 HTML과 홈 런타임 메타의 제목·설명·OG·Twitter 값을 일치시킨다.
3. 홈과 활동 페이지의 메타 갱신 기준을 한 곳으로 정리해 중복과 이전 페이지 값의 잔류를 막는다. 스크롤 동작은 유지한다.
4. `/activity`의 canonical과 `og:url`은 활동 URL을 사용한다. 홈 복귀 시 홈 값으로 돌아오게 한다.
5. `/admin`, `/workshop-preview`는 `noindex` 대상으로 정리한다. 이는 접근 제어를 대신하지 않는다. 공개 페이지 복귀 시 이전 `noindex`가 남지 않게 한다.
6. 현재 `og-image.png`, favicon 자산을 유지한다. 미리보기의 `og:url`이 공개되지 않은 `/workshop`을 가리키는 문제도 정리한다.
7. 공개 URL만 포함하는 sitemap과 robots.txt를 준비한다. `/workshop` 리다이렉트는 유지하며 사이트맵에는 넣지 않는다.

공유 확인은 초기 HTML 응답과 실제 공유 미리보기를 함께 점검한다. 경로별 초기 HTML이 필요하다는 결과가 나오면 별도 사전 렌더링 작업으로 산정한다. P0에서 프레임워크를 교체하지 않는다.

수정 예상 파일: `index.html`, `src/App.tsx`, `src/components/ActivityPage.tsx`, `src/components/WorkshopPage.tsx`의 메타 처리 부분, 필요 시 `public/robots.txt`, `public/sitemap.xml`.

## 4. P1: 교육 운영과 12월 모집을 위한 후속 확장

이전 채팅의 교육 사업 목표를 달성하기 위한 다음 단계다. 현재 P0 코드 수정 범위 밖이며, 새 경로·콘텐츠 구조를 정한 뒤 별도 구현한다.

### 메인과 교육 상세 화면의 역할

- 메인: 브랜드, 제작물, 활동 근거를 보여주고 문의로 연결한다.
- 교육 상세: 누가 가르치는지, 무엇을 완성하는지, 일정·조건이 무엇인지 설명하고 상담·신청으로 연결한다.
- 활동 페이지: 교육 현장·보도·사례의 근거를 제공한다.

교육 공개 경로는 후속 작업에서 하나로 확정한다. 과거 사용자가 처음 제안한 `/ai-education`을 후보로 두되, 이후 `/workshop` 구현 이력과 현재 리다이렉트 정책을 함께 고려한다. 이전 답변에서 제안한 `/education`을 이미 승인된 경로처럼 추가하지 않는다. 기존 `/workshop`과 `/workshop-preview`는 현재 역할을 보존한다.

### 교육 상세 화면 구성안

| 순서 | 영역 | 표시 내용 |

| 3 | 교육 근거 | 검증된 실적 3개 이내 + 대표 사례 1개 + 기존 활동 페이지 연결 |

시각 원칙:

- 한 영역에 큰 제목 하나, 짧은 설명, 대표 이미지 하나를 우선한다.
- 강사진 전체·과정 전체·보도 전체를 메인에 추가하지 않는다.
- 현재 워크숍 전용 네이비·오렌지·틸 토큰은 유지한다. 기존 미리보기의 전체 스타일을 홈으로 가져오지 않는다.
- `WorkshopPage`의 과정·FAQ·강사 소개는 내용 자산으로 재검토한다. 현행 경력의 근거와 두 번째 코치의 공개 이름·사진을 확인한다.

### 강사 신뢰 정보와 실적 기준

강사별 표시안:

```text
[실제 프로필 사진]
이름 / 담당 분야
어떤 대상에게 무엇을 가르치는지 한 문장

누적 강의시간 / 누적 교육 참여인원 / 출강 기관 수
집계 기간과 기준일

대표 교육 사례 → 기존 활동 자료
```

운영 기록에 필요한 항목:

| 구분 | 필요한 자료 |
| --- | --- |
| 강사 | ID, 이름, 소개, 전문 분야, 실제 사진, 공개 가능한 경력과 근거 |
| 강의 | 강의 ID, 과정 ID, 담당 강사, 기관, 날짜, 실제 강의시간, 실제 참여인원, 완료 상태, 확인 자료 |
| 검증 | 기록별 확인 여부, 집계 기준일, 중복 제외 기준 |
| 모집 과정 | 담당 강사, 일정, 시간, 정원, 비용, 장소/온라인 방식, 신청 URL, 모집 마감, 상태 |

집계 원칙:

- 강의시간은 완료·확인된 실제 수업 시간만 합산한다. 준비·이동 시간은 제외한다.
- 공동강의는 강사별 실제 참여 시간을 기록한다. 팀 전체 시간은 같은 수업을 중복 합산하지 않는다.
- 인원은 “누적 교육 참여인원(연인원)” 또는 “중복 제외 수강생” 중 실제 계산 가능한 기준을 명시한다.
- 동일 교육의 사진·기사·활동 카드가 여러 개여도 하나의 강의로 처리한다.
- 출강 기관 수는 표기 차이를 정리한 기관 단위로 중복 제외한다.
- 확인되지 않은 숫자는 숨긴다. 기존 사진과 활동 근거로 신뢰를 보여주고, 예시 숫자나 0을 실제 실적처럼 공개하지 않는다.
- 과거 시안의 3,200시간·4,800명 등은 검증된 값이 아니므로 사용하지 않는다.

현재 활동 기본 데이터에는 `2024.08` 표시와 별도 `createdAt` 정렬값이 함께 있다. 공개 실적을 만들기 전 실제 교육 날짜·보도일·등록일을 구분해 확인한다. 카드 설명의 16명·20여 명을 누적 수강생으로 단순 합산하지 않는다.

### 12월 클래스 운영 상태

기준 월은 2026년 12월이다. 현재 소스만으로 확정된 12월 일정을 확인할 수 없다.

| 상태 | 표시/동작 |
| --- | --- |
| 준비 중 | 모집 일정 안내 예정. 수강 신청 버튼은 숨긴다. |
| 모집 중 | 확정 정보와 실제 신청폼을 제공한다. |
| 마감 | 신청을 닫고, 대기 접수를 운영할 때만 해당 폼을 연결한다. |
| 종료 | 모집 버튼을 내리고 결과·후기·활동 기록으로 연결한다. |

기관 교육 문의는 맞춤 상담 폼, 개인 클래스는 해당 과정 신청폼으로 연결한다. 신청폼의 과정명·날짜·비용과 페이지 표시가 같은지 공개 전에 확인한다. 과거 1기 가격·할인·정원은 새로운 12월 과정에 자동 적용하지 않는다.

## 6. 준비할 자료와 측정 기준
